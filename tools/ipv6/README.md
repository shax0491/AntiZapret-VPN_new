# IPv6 на узлах (03.11.2026)

- `nft-az-nat66.nft` + `az-nat66.service`: NAT66 для клиентов по ULA и изоляция клиентов друг от друга (стоят на DE1, DE2, DE4, NL2).
- Рабочий нативный IPv6: DE1 (`2602:fc16:2:6df::ec5a/64`, шлюз хостера `2602:fc16:2:600::1`) и NL2 (`2a12:9080:9:2b::a/64`, шлюз `2a12:9080:9::1`). Нужно `net.ipv6.conf.<iface>.disable_ipv6=0` и `net.ipv6.conf.all.forwarding=1` (`/etc/sysctl.d/99-ipv6-forward.conf`), иначе `99-disable-ipv6.conf` от AntiZapret глушит адрес.
- DE2 и DE4: статика (netplan `60-ipv6.yaml`, адреса `::a`, `::b`, `::c`), маршрутизатор хостера не отвечает на NS шлюза `2a0c:4ac1:4::1` ни с одного из них, unsolicited NA не помог - IPv6 не работает, нужен тикет хостеру; в `/etc/gai.conf` стоит предпочтение IPv4.
- Proton IPv6 включён (03.11) на NL2, DE2, DE4, FR1: в `/etc/wireguard/proton.conf` `AllowedIPs = 0.0.0.0/0, ::/0`, в `PostUp` адрес `2a07:b944::2:2/128` + `disable_ipv6=0` на интерфейсе + `ip -6` маршрут/правило таблицы 51820 (Address v4-only, иначе wg-quick падает при `disable_ipv6=1`); `proton-pick` эти строки не трогает (правит только PublicKey/Endpoint/PrivateKey, `AllowedIPs` берёт у живого пира). outbound `proton` там `UseIPv4v6`. Проверено клиентом: VLESS → NL2 → Proton, выход `2a00:7c80:0:3a9::14`. DE1 тоже включён (выход Proton `2a02:6ea0:1703:3101::19`, прямой `2602:fc16:2:6df::ec5a`); FI1/LV1 - без изменений (`UseIPv4`).
- (устарело, до 03.11) xray: outbound `proton` - `domainStrategy: UseIPv4` (наши конфиги Proton выданы только с IPv4-адресом; тест 03.11 с адресом `2a07:b944::2:2/128` и `AllowedIPs ::/0` показал рабочий IPv6 через Proton на DE2, DE4, NL2, FR1, не работает на FI1 и LV1); `direct` - `UseIPv4v6` на DE1 и NL2, `UseIPv4` на остальных.
- AAAA клиентам AntiZapret/VPN подавляет `kresd` (экземпляры 127.1.1.1 и 127.2.2.2), настоящие AAAA отдаёт только внутренний резолвер 127.3.3.3.

- Интерфейс `vpn` (WG, `/etc/wireguard/vpn.conf`): в `[Interface]` добавлен `PostUp = sysctl -q -w net.ipv6.conf.%i.disable_ipv6=0; ip -6 addr replace fdaf:2800:8::1/64 dev %i`. Подсеть `fdaf:2800:8::/64` входит в `fdaf:2800::/32`, NAT66 (`nft-az-nat66.nft`, `masquerade` через `enp3s0`) уже её покрывает; `net.ipv6.conf.all.forwarding=1`.
- Клиент: `Address = 10.28.8.X/32, fdaf:2800:8::X/128`, `AllowedIPs = 0.0.0.0/0, ::/0`, `DNS = 1.1.1.1, 2606:4700:4700::1111` (Full VPN использует публичный DNS, `kresd` не участвует). Проверено клиентом в netns на узле: `ping6` 0% потерь, `curl -6` показывает выход `2a12:9080:9:2b::a`, traceroute `fdaf:2800:8::1 -> 2a12:9080:9::1 -> …`. Тестовый клиент `test-ipv6` (10.28.8.252 / fdaf:2800:8::252) оставлен в `vpn.conf` до решения владельца.
- Профиль AntiZapret (split) по IPv6 НЕ реализован: `kresd.conf` отвечает `::` на AAAA (`zero_aaaa_answer`, строки 109 и 183) и `net.ipv6 = false` (248), а `proxy.py` строит только IPv4-карту фиктивных адресов (`nft map ip antizapret mapping`, `ipv4_addr : ipv4_addr`). Для v6 нужны: таблица `ip6 antizapret` с картой `ipv6_addr : ipv6_addr`, ветка AAAA в `proxy.py`, снятие `zero_aaaa_answer` для списочных доменов, v6-адреса на `antizapret`/`antizapret2`/AWG-интерфейсах и перевыпуск клиентских профилей. AdminPanelAZ (генератор профилей) под v6 не менялся.

## Поправки 03.11.2026 (поздно вечером)

- Xray `domainStrategy`: `UseIPv4v6` = «сначала IPv4, IPv6 только если нет A» - реальный клиентский трафик через такой outbound выходит по IPv4. Чтобы Proton-выход шёл по IPv6, нужен `UseIPv6v4`. Включён только на DE2 (проверено: клиентские запросы через роутер дают IPv6-SYN `2a07:b944::2:2` -> Google v6 на интерфейсе `proton`). На DE1/DE4/NL2/FR1 остаётся `UseIPv4v6`: у Xray нет fallback на IPv4, если IPv6-путь до сайта через Proton сломан.
- Тестовый клиент `test-ipv6` на NL2: чистый WireGuard на 51080 режется ТСПУ (handshake проходит, данные - нет). Рабочий формат - профиль AWG 1.5 (`-am.conf`, `I1`, порт 52080: `PREROUTING REDIRECT 52080 -> 51080`), его и выдавать клиентам в РФ.
- Фильтр tcpdump `tcp[tcpflags]` для IPv6 не работает - для IPv6 фильтровать только по `ip6 and tcp port 443` и считать `Flags [S]` в выводе.
